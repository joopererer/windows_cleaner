## 📖 核心理念与 V2.4.1 架构演进

传统的磁盘清理工具往往追求“暴力一键清空”，在面对现代复杂的多语言开发环境时，极易误删重要包依赖、破坏项目配置或造成未提交编译产物不可逆丢失。

**Windows Disk Clean Master V2.4.1（项目关联智能检测、fnm 兼容与进度细化版）** 在前代安全版本的基础上完成了重要升级与细节修正：

### 1. 项目关联进程精准识别（告别全局“一刀切”阻断）
- **过去痛点**：早期版本只要检测到系统后台有任何 Java/Dart 等常驻后台进程，就会一刀切地阻止所有项目的清理与隔离，造成误报阻断。
- **智能分级机制**：
  - **明确关联（硬阻断）**：若进程命令行参数包含当前项目的绝对路径，或可执行文件位于候选构建目录内（如正在运行的测试程序），**强制阻断隔离**；
  - **归属不确定（软警示 + 显式确认）**：若系统中有未明确绑定项目路径的编译器/Java进程，列出 PID 与进程名；逐项确认时需确认接受风险并输入 `QUARANTINE`；批量确认时需先输入 `ACCEPT-RISK` 二次授权，再输入 `BATCH-QUARANTINE`；
  - **明确指向其他项目（安全放行）**：若命令行清晰指向其他路径下的项目，不干扰当前项目的隔离；
  - **Fail-Closed 容灾策略**：CIM/WMI 查询异常时直接拒绝隔离；真正移动前再次查询进程状态并复核目录内容。

### 2. fnm (Fast Node Manager) 原生兼容与环境智能装配
- **问题场景**：`fnm` 默认在交互式 Shell Profile 中动态注入 PATH，而工具通过 `-NoProfile` 启动时往往无法直接识别 `node.exe`，导致误报或无法检测 npm 缓存。
- **安全装配**：
  - 自动检测并初始化 `fnm`，**仅在当前脚本进程内**动态注入 Node 运行时环境，**绝不修改系统或用户的永久全局 PATH**；
  - 优先调用当前 `node.exe` 同目录配套的 `npm.cmd`，避免误用 `AppData\Roaming` 下过期的全局 shim；
  - 修复了对 `fnm use` 的参数兼容性问题，提供清晰的诊断与维护指引。

### 3. 透明非虚构的真实进度反馈
- 识别项目时实时高频显示：已检查目录数、已发现候选数、队列深度、耗时秒数及当前扫描路径；
- 统计大型 `build`/`target` 目录时，实时显示已统计文件数与子目录数；
- 采用不确定总量（Indeterminate）的真实进度反馈，杜绝虚假百分比。针对 Windows 下枚举数十万微小文件可能产生的短暂 I/O 停顿提供友好提示。

### 4. 完整的安全基因传承
- **菜单 1**：用户级 `%TEMP%` 纯文件级递归扫描（支持 7/14/30 天选项，深度排除源码、配置、锁文件、数据库及压缩包，独占打开占用测试，移入回收站，不删整目录，不删空目录）；
- **菜单 2**：全局包依赖（Gradle/Pub/npm）永久锁定保护；项目扫描前置只读预检（Preflight），提供【取消】、【批量隔离预检合格项】、【逐项确认】三种灵活操作模式；
- **同卷安全隔离区（Quarantine）与 7 天冷静期**：构建产物移至同分区 `.wdcs-quarantine`，不产生跨卷数据损坏风险，状态持久化记录；隔离未满 7 天受保护，满 7 天后需输入 `PURGE <ID>` 彻底销毁；
- **菜单 8 专用原路无损恢复**：一键原路恢复，禁止覆盖已有同名目录；
- **菜单 3 跨卷安全迁移**：冗余空间预检 + 4 线程 Robocopy + **全量 SHA256 哈希校验** + 本地改名备份 + 自动回滚 + NTFS Junction；
- **完全只读模块**：菜单 4（安装路径）、菜单 5（内存排行）、菜单 7（全盘审计报告，无删除按钮）；
- **立体防护网**：内置系统核心目录硬保护 + [`protected-paths.txt`](protected-paths.txt) 用户自定义绝对路径白名单 + 软链接/Junction 穿透阻断。

| **2** | **[开发瘦身] 依赖只读与项目产物安全隔离** | • **全局依赖保护**：Gradle Wrapper/caches、Dart Pub Cache、npm cache 等标记为 `[PROTECTED]` 只读展示大小，绝不删除；<br>• **fnm 兼容与 npm 维护**：支持 `fnm` 进程级无污染装配；提供可选的 `npm cache verify` 索引校验与整理；<br>• **项目关联进程识别**：硬阻断当前项目关联进程；对不确定归属进程提示预警；<br>• **项目扫描与特征感知**：严格验证项目结构后仅列出对应 `build` 或 `target`；实时呈现项目源码与构建产物的改动时间；<br>• **只读预检与三种操作模式**：输入范围（如 `1-3, 5`）后先进行只读预检，可选择【取消】、【批量隔离合格项（需输入 BATCH-QUARANTINE，不确定项需先输入 ACCEPT-RISK）】或【逐项确认（每项确认 QUARANTINE）】。 |
| **3** | **[无感迁移] 跨卷目录安全迁移** | • **前置空间预检**：目标卷必须剩余至少 `源体积 × 1.1 + 100MB` 可用空间；<br>• **4线程 Robocopy 搬迁**：执行带错误控制的完整数据复制；<br>• **严格 SHA256 校验**：复制完成后对所有文件逐一进行 SHA256 强哈希校验；<br>• **回滚备份与安全软链**：校验通过后将源目录重命名为 `.wdcs-backup-yyyyMMdd-HHmmss` 保留本地备份，再建立 NTFS Junction（`mklink /J`）；如遇异常自动完整回滚，绝不破坏源数据。 |

| **5** | **[内存优化] 查看进程内存占用** | **完全只读**。按物理工作集从大到小列出占用内存最高的前 15 个后台进程，不再强制调用 `EmptyWorkingSet`，避免引发应用进程发生内存颠簸与卡顿。 |
| **6** | **[实时监护] C 盘剩余空间监控** | 启动轻量级后台轮询监控（每 5 分钟），当系统盘可用空间低于 **5.0 GB** 时弹出系统级桌面通知，预防编译器突发爆盘。 |
| **7** | **[全盘审计] 卸载残留与大文件报告** | **完全只读报告，无删除按钮**。<br>• 扫描指定盘符，识别可疑项目目录（`node_modules`、`build`、`target` 等）及 14 天前大于 100MB 的旧安装包/压缩包；<br>• 生成分析报告并保存至 `%LOCALAPPDATA%\WinDiskCleanSafe\logs`，可在 `Out-GridView` 表格中交互查阅，绝不提供批量删除按钮（因文件名和修改时间不能作为安全删除证据）。 |

## 🚀 快速上手与运行

### 运行环境要求
- **操作系统**：Windows 10 / Windows 11 / Windows Server 2016+
- **环境要求**：Windows PowerShell 5.1 或更高版本（系统自带，无需额外安装）
- **终端推荐**：Windows Terminal，控制台默认支持 UTF-8（代码内自动调用 `chcp 65001`）

### 启动方式

#### 方式一：一键双击运行（推荐）
直接鼠标双击运行根目录下的 **`win-disk-clean-master.bat`**。
> 该脚本会自动配置 UTF-8 编码，以当前登录用户身份拉起 PowerShell 核心，**无需管理员提权**，无需修改永久执行策略。

#### 方式二：在 PowerShell 终端中执行
进入项目所在目录并执行：
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\win-disk-clean-master.ps1"
```
或者在已开启的 PowerShell 会话中直接运行：
```powershell
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$PWD\win-disk-clean-master.ps1"
```

## 🛡️ 保护范围与 `protected-paths.txt` 说明

为了防止任何误操作风险，V2.4.1 构建了立体防护系统：

### 1. 内置受保护路径
系统自动锁死以下路径及其子目录，任何扫描与迁移操作均不可将其作为目标：
- 卷根目录（如 `C:\`, `D:\`）
- 系统核心目录：`%windir%`, `C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData`
- 用户核心资料库：`Desktop`, `Documents`, `Pictures`, `Music`, `Videos`, `Downloads`, `OneDrive`
- 本工具日志与清单库：`%LOCALAPPDATA%\WinDiskCleanSafe`

### 2. 用户自定义保护清单 (`protected-paths.txt`)
您可以在根目录的 [`protected-paths.txt`](protected-paths.txt) 中追加自定义需要绝对保护的目录（每行一个完整绝对路径，支持 `#` 注释）：
```text
# 每行一个绝对路径，程序将完全保护其不被迁移、不被遍历、不被隔离
D:\Projects\ProductionApp
E:\ImportantBackups
```

## ⚠️ 限制与安全须知

1. **修改时间非绝对安全证明**：文件的最后修改时间只是筛选线索，不能百分之百证明文件已无价值。用户 TEMP 目录中亦可能存放着尚未完成的软件会话或安装包缓存，请在移入回收站前审阅候选分组及大文件列表。
2. **独占打开检查说明**：独占打开校验可以极大程度降低清理正在使用中文件的风险，但无法完全杜绝扫描到删除瞬间的微小并发竞争窗口。
3. **回收站与空间释放**：菜单 1 移入回收站后，磁盘可用空间通常不会立即增加，需要用户后续自行确认无误后清空回收站才会真正释放。
4. **大型目录枚举停顿说明**：在执行项目扫描或构建产物统计时，若单个目录下包含数以十万计的细碎文件，`Get-ChildItem` 在底层枚举过程中可能产生短暂的界面更新停顿，此属于 Windows 文件系统正常现象，并非程序卡死。
5. **语法自检方式**：
   在 PowerShell 中运行以下命令可验证脚本语法完整性：
   ```powershell
   $tokens = $null; $errors = $null
   [void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path '.\win-disk-clean-master.ps1').Path,[ref]$tokens,[ref]$errors)
   $errors | Select-Object Message,@{N='Line';E={$_.Extent.StartLineNumber}}
   ```
   若无任何输出，即表示语法解析完全合规。
6. **免责说明**：本工具为开源辅助运维脚本，运行任何具备文件操作能力的工具均存在客观环境差异风险，对核心项目操作前建议做好独立异地备份。
