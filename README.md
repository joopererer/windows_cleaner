## 📖 核心理念与 V2.3 架构升级

传统的磁盘清理工具往往追求“暴力一键清空”，在面对复杂的多语言开发环境时，极易误删重要包依赖、破坏项目配置或造成未提交编译产物不可逆丢失。

**Windows Disk Clean Master V2.3（安全文件级 TEMP 清理与工程感知版）** 在 V2.1/V2.2 的安全基石上完成了重磅演进：
- **菜单 1 革命性升级：文件级精准扫描（不再整目录粗暴处理）**：
  - 传统做法常因目录内包含一个新文件就放弃整个目录，或因文件夹陈旧而暴力整删；V2.3 彻底改为**按单体文件深度递归检测**；
  - 严格限定在当前登录用户的 `USERPROFILE` 下的 `TEMP` 目录，绝不越权触碰系统级 `Windows\Temp`、`Windows Update` 或清空已有回收站；
  - 提供 **7 天（默认）、14 天、30 天** 灵活的保留天数选项，支持用户根据场景灵活调整保护窗口；
  - **绝不执行空目录删除，不存在整目录级联删除行为**，候选文件在移入回收站前进行**独占文件打开校验（检测进程占用）**与属性重检；
  - 全方位保守排除重要文件类型（代码/脚本、配置/锁文件、压缩包/镜像、文档媒体等）与工程依赖子树（`.git`、`node_modules` 等）。
- **菜单 2 开发构建产物管理大幅强化**：
  - **活动构建进程实时拦截**：检测到 `cargo`、`rustc`、`flutter`、`dart`、`gradle`、`java`、`mvn`、`cmake` 等相关进程运行时，主动拦截隔离操作，防止破坏进行中的编译；
  - **项目与构建活动迹象呈现**：对比项目源文件（`src`、`lib`、`test`）与构建目录的最新变动时间，清晰呈现项目活跃度；
  - **磁盘分区逻辑分组展示**：扫描结果按所属磁盘（`C:`、`D:`、`E:` 等）分组展示数量与空间占用；
  - **批量编号选择支持**：支持 `1,3,5` 或 `1-10` 乃至混合模式批量输入，每项隔离前均会执行二次确认与进程占用复检。
- **全局依赖仓库永久锁定**：Gradle Wrapper/caches、Dart Pub Cache、npm cache 等一律标记为 `[PROTECTED]` 只读展示，绝不自动清理；
- **同卷安全隔离区（Quarantine）与 7 天冷静期**：
  - 构建产物移入项目同分区的 `.wdcs-quarantine` 专用隔离区；
  - 必须隔离满 7 天才允许进入永久删除候选，永久删除需严格输入 `PURGE <ID>` 进行二次确认；
  - 支持通过菜单 8 一键原路无损恢复（禁止覆盖已有文件）。
- **迁移强校验与自动回滚**：跨卷目录迁移前检测空间冗余，迁移后执行全文件 **SHA256 哈希强比对**，并保留重命名备份与自动回滚机制；
- **立体防护网**：内置核心系统目录防护 + [`protected-paths.txt`](protected-paths.txt) 自定义绝对路径白名单 + 拒绝跟随符号链接/Junction 穿透。

## 🛠️ 功能模块详述 (1 ~ 9)

| 菜单编号 | 功能模块 | 安全策略与实现细节 |
| :---: | :--- | :--- |
| **1** | **[一键清理] 用户临时文件 (文件级安全版)** | • **限定范围**：仅扫描当前登录用户的 `%USERPROFILE%\AppData\Local\Temp`，拒绝系统级路径；<br>• **保留天数**：可选保留最近 **7 天（默认）、14 天或 30 天** 内活跃修改的文件；<br>• **逐文件安全排除**：自动过滤代码/脚本（`.exe/.dll/.bat/.ps1/.js/.py/.rs` 等）、配置文件/锁文件（`.json/.yaml/.toml/lock` 等）、数据库、压缩包、文档/媒体，以及嵌套其中的工程依赖子树（`.git/node_modules/.gradle` 等）；<br>• **分组与大文件展示**：按顶层来源目录统计并展示体积最大的候选文件；<br>• **移入回收站**：逐文件重检修改时间、排查只读/系统属性并做**独占打开占用测试**，输入 `RECYCLE` 确认后安全移入回收站（可反悔）。**不执行任何整目录或空目录删除**。 |
| **2** | **[开发瘦身] 依赖只读与项目产物安全隔离** | • **全局包依赖保护**：Gradle Wrapper/caches、Dart Pub Cache、npm cache 等标记为 `[PROTECTED]` 只读展示大小，绝不删除；<br>• **构建进程安全拦截**：检测到 `cargo`、`rustc`、`flutter`、`dart`、`java`、`mvn` 等编译进程时，主动中断并提醒关闭，防止破坏正在编译的工程；<br>• **项目扫描与特征感知**：输入项目根目录（如 `D:\Projects`），严格验证特征后仅列出对应的 `build` 或 `target`；<br>• **磁盘分组与活动迹象**：按所属磁盘分区聚合展示，呈现项目源码与构建产物的最新改动时间；<br>• **批量编号选择与隔离**：支持单选、逗号分隔或范围输入（如 `1-3, 5`），逐项确认 `QUARANTINE` 后安全移动至同卷 `.wdcs-quarantine` 隔离区。 |
| **3** | **[无感迁移] 跨卷目录安全迁移** | • **前置空间预检**：目标卷必须剩余至少 `源体积 × 1.1 + 100MB` 可用空间；<br>• **4线程 Robocopy 搬迁**：执行带错误控制的完整数据复制；<br>• **严格 SHA256 校验**：复制完成后对所有文件逐一进行 SHA256 强哈希校验；<br>• **回滚备份与安全软链**：校验通过后将源目录重命名为 `.wdcs-backup-yyyyMMdd-HHmmss` 保留本地备份，再建立 NTFS Junction（`mklink /J`）；如遇异常自动完整回滚，绝不破坏源数据。 |
| **4** | **[目录迁移] 查看软件安装路径** | **完全只读**。安全读取并展示注册表中的 `ProgramFilesDir` 和 `ProgramFilesDir (x86)` 当前指向，不擅自修改全局注册表，倡导在具体软件安装器中自行选择路径。 |
| **5** | **[内存优化] 查看进程内存占用** | **完全只读**。按物理工作集从大到小列出占用内存最高的前 15 个后台进程，不再强制调用 `EmptyWorkingSet`，避免引发应用进程发生内存颠簸与卡顿。 |
| **6** | **[实时监护] C 盘剩余空间监控** | 启动轻量级后台轮询监控（每 5 分钟），当系统盘可用空间低于 **5.0 GB** 时弹出系统级桌面通知，预防编译器突发爆盘。 |
| **7** | **[全盘审计] 卸载残留与大文件报告** | **完全只读报告，无删除按钮**。<br>• 扫描指定盘符，识别可疑项目目录（`node_modules`、`build`、`target` 等）及 14 天前大于 100MB 的旧安装包/压缩包；<br>• 生成分析报告并保存至 `%LOCALAPPDATA%\WinDiskCleanSafe\logs`，可在 `Out-GridView` 表格中交互查阅，绝不提供批量删除按钮（因文件名和修改时间不能作为安全删除证据）。 |
| **8** | **[隔离恢复] 恢复已隔离的构建产物** | 读取隔离索引清单，将处于 `Quarantined` 状态的目录一键**原路无损恢复**回项目目录；若原路径已存在同名目录则严格拒绝覆盖。 |
| **9** | **[隔离清理] 永久回收隔离空间** | 真正物理回收磁盘空间的唯一入口：<br>• **必须隔离满 7 天** 才会出现在候选列表中；<br>• 每次仅限选中 1 项；<br>• 必须严格输入 `PURGE <ID>`（如 `PURGE 1a2b3c...`）进行防误触二次确认后才执行永久物理清除。 |

## 🚀 快速上手

### 运行环境要求
- **操作系统**：Windows 10 / Windows 11 / Windows Server 2016+
- **环境要求**：Windows PowerShell 5.1 或更高版本（系统自带，无需安装任何额外依赖）
- **终端推荐**：Windows Terminal，控制台默认支持 UTF-8（代码内自动调用 `chcp 65001`）

### 启动方式

#### 方式一：一键双击运行（推荐）
直接鼠标双击运行根目录下的 **`win-disk-clean-master.bat`** 即可。
> 该脚本会自动配置 UTF-8 编码，以当前登录用户身份拉起 PowerShell 核心，**无需管理员提权**。

#### 方式二：在 PowerShell 终端中执行
进入项目所在目录并执行：
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\win-disk-clean-master.ps1"
```
或者在当前 PowerShell 会话中直接运行：
```powershell
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$PWD\win-disk-clean-master.ps1"
```

## 🛡️ 保护范围与 `protected-paths.txt` 说明

为了防止任何误操作风险，V2.3 构建了立体防护系统：

### 1. 内置受保护路径
系统自动锁死以下路径及其子目录，任何扫描与迁移操作均不可将其作为目标：
- 卷根目录（如 `C:\`, `D:\`）
- 系统核心目录：`%windir%`, `C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData`
- 用户核心资料库：`Desktop`, `Documents`, `Pictures`, `Music`, `Videos`, `Downloads`, `OneDrive`
- 本工具日志与清单库：`%LOCALAPPDATA%\WinDiskCleanSafe`

### 2. 用户自定义保护清单 (`protected-paths.txt`)
您可以在根目录的 [`protected-paths.txt`](protected-paths.txt) 中追加自定义需要绝对保护的目录（每行一个完整绝对路径，支持 `#` 注释）：
```text
# 每行一个绝对路径，程序将完全保护其不被迁移、不被遍历、不被隔离
D:\Projects\ProductionApp
E:\ImportantBackups
```

## ⚠️ 限制与安全须知

1. **修改时间非绝对安全证明**：文件的最后修改时间只是筛选线索，不能百分之百证明文件已无价值。用户 TEMP 目录中亦可能存放着尚未完成的软件会话或安装包缓存，请在移入回收站前审阅候选分组及大文件列表。
2. **独占打开检查说明**：独占打开校验可以极大程度降低清理正在使用中文件的风险，但无法完全杜绝扫描到删除瞬间的微小并发竞争窗口。
3. **回收站与空间释放**：菜单 1 移入回收站后，磁盘可用空间通常不会立即增加，需要用户后续自行确认无误后清空回收站才会真正释放。
4. **离线依赖与专有构建输出**：若您的项目依赖本地手写的专有输出产物或离线资源，请勿随意隔离。若出现误操作，可立刻通过 **菜单 8 [隔离恢复]** 原路无损召回。
5. **用户上下文一致性**：若以其他管理员身份或不同账户运行脚本，`USERPROFILE` 和 `TEMP` 将指向该管理员账户；建议始终在当前日常开发使用的用户会话中运行，无需额外提权。
6. **免责说明**：本工具为开源辅助运维脚本，运行任何具备文件操作能力的工具均存在客观环境差异风险，对核心项目操作前建议做好独立异地备份。
